<h1 align='center'>models.py</h1>

> В данном файле описана иерархия классов для представления различных типов транспортных средств.

## Импорты:

### Глобальные:

* `datetime` - date (Для корректной работы с датами выпуска автомобилей).

* `dataclasses` - dataclass (Для декларативного описания классов данных).

### Базовый класс Car:

#### Атрибуты:

* `id` - Уникальный целочисленный идентификатор объекта (type: int)

* `brand` - Строковое название марки производителя (type: str)

* `model` - Строковое название модели (type: str)

* `mileage` - Текущий пробег автомобиля в километрах (type: int)

* `year_of_manufacture` - Дата производства автомобиля (type: date)

#### Методы:

* `__str__` - Возвращает форматированную строку с информацией об автомобиле (type: str)

* `to_dict` - Подготавливает данные объекта для сериализации в JSON, добавляя поле типа (type: dict)

### Класс ElectricCar (Наследник Car):

#### Дополнительные атрибуты:

* `battery_capacity` - Емкость аккумуляторной батареи (type: int)

* `charge_level` - Текущий уровень заряда в процентах (type: int)

### Класс SportCar (Наследник Car):

#### Дополнительные атрибуты:

* `max_speed` - Предельная скорость автомобиля (type: int)

* `acceleration` - Время разгона до 100 км/ч (type: float)

<h1 align='center'>app.py</h1>

> Модуль app.py реализует слой бизнес-логики (Service Layer). 
> Он изолирует внутреннее состояние коллекции и правила обработки данных от интерфейса пользователя.

## Импорты:

### Глобальные:

* `typing` - Callable, Any (Для поддержки функций высшего порядка и гибкой типизации).

### Локальные:

* `models` - Доменные модели транспортных средств.

* `exceptions` - Кастомные исключения для обработки ошибок логики.

* `storage` - Функционал для работы с файловой системой.

### Класс CarApp:

#### Атрибуты:

* `_storage_path` - Путь к файлу для сохранения состояния (type: str)

* `_cars` - Инкапсулированный список объектов автомобилей (type: list[Car])

#### Основные методы:

* `add_car` - Добавление автомобиля в коллекцию с валидацией уникальности ID (type: None).

* `delete_car` - Удаление автомобиля из коллекции по идентификатору (type: None).

* `find_car_by_id` - Поиск и получение объекта автомобиля по ID (type: Car).

* `get_all_cars` - Получение полного списка всех автомобилей в гараже (type: list[Car]).

* `filter_cars` - Фильтрация коллекции на основе переданной функции-предиката (type: list[Car]).

* `sort_cars` - Сортировка элементов коллекции по заданному ключу (type: None).

* `save_data` / `load_data` - Команды для синхронизации состояния с диском (type: None).

<h1 align='center'>cli.py</h1>

> Модуль cli.py содержит Presentation Layer приложения. 
> Реализует интерактивное взаимодействие через консоль.

## Компоненты класса ConsoleInterface:

#### Диспетчеры (Словари):

* `_actions` - Карта соответствия пунктов меню методам интерфейса.

* `_creators` - Карта соответствия типов транспорта функциям их создания.

#### Методы диалогов:

* `_display_cars` - Вывод коллекции в виде структурированного списка.

* `_add_car_dialog` - Пошаговый сбор параметров для создания новой записи.

* `_search_dialog` - Поиск автомобиля по различным атрибутам (марка, модель).

* `_filter_dialog` - Применение технических фильтров к отображаемым данным.

* `_delete_car_dialog` - Удаление объекта с обязательным подтверждением действия.

* `run` - Главный управляющий цикл приложения.

<h1 align='center'>storage.py</h1>

> Модуль storage.py отвечает за персистентность (Сохранение состояния объекта сразу после его инициализации) данных (Data Access Layer). 
> Обеспечивает корректное преобразование объектов Python в формат JSON и обратно.

## Основные функции:

* `save_collection` - Сериализация списка объектов в файл. Автоматически создает директорию Saved при её отсутствии.

* `load_collection` - Десериализация данных из JSON файла. Восстанавливает конкретные типы объектов (Car, ElectricCar, SportCar) на основе метаданных.

#### Логика восстановления:

* Используется `types_map` для сопоставления строкового идентификатора типа с соответствующим классом.

* Производится автоматическое преобразование строк дат обратно в объекты `datetime.date`.

<h1 align='center'>validate.py</h1>

> Набор инструментов для обеспечения целостности данных на входе в систему.

* `validate_id` - Гарантирует, что идентификатор является положительным числом.

* `validate_string` - Исключает возможность ввода пустых или некорректных текстовых полей.

* `validate_mileage` - Проверяет пробег на соответствие физическим границам (неотрицательность).

* `validate_year` - Ограничивает год выпуска периодом от 1886 года до текущей даты.

* `validate_positive_int` / `validate_positive_float` - Универсальные проверки для числовых параметров.
